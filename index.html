A rule that automatically sends an email response to a Lead or Case submission based on record attributes.

Salesforce server-side programming language used for custom business logic that runs in Salesforce transactions.

Apex code that executes in response to record events such as create, update, delete, or undelete.

A Flow without screens that is typically invoked by another Flow, Apex, or automation process.

Budget, Authority, Need, and Timeline, a qualification framework used to determine whether a lead is a good sales fit.

B

B

BlackTab

Administrative console used to support customers and troubleshoot org issues.

B

Apex design that processes collections of records efficiently instead of doing repetitive work one record at a time.

The central support record used to track a customer issue from intake through investigation, communication, and resolution.

A timeline-style feed on a case that shows actions, updates, emails, and collaboration tied to the support record.

C

A related case linked under a parent case so the issue can be tracked separately while remaining connected to a broader problem.

C

CRUD

Create, Read, Update/Edit, Delete, the object-permission model used to define what actions a user can perform.

Duplicate Rule

The duplicate-management rule that determines what Salesforce does after a potential duplicate is detected, such as allowing, warning, or blocking.

D

Dynamic Forms & Actions

Lightning capabilities that conditionally show or hide fields and actions based on criteria such as record data or user context.

D

Dependent Picklist

A picklist whose available values are filtered by the value selected in a controlling field. Example: Country controls which State or Province values are available.

D

DML

Data Manipulation Language operations that insert, update, delete, or otherwise change Salesforce records.

Salesforce AI-assisted capabilities for service work, such as case summarization, Knowledge suggestions, and drafted responses that still require human validation.

E

A support eligibility or service commitment record that can define what level of service a customer should receive.

E

A runtime error that identifies where execution failed. The exception location is a starting clue and may not be the underlying root cause.

A sales forecasting classification such as Pipeline, Best Case, Commit, Closed, or Omitted that helps leadership estimate expected revenue.

Controls whether a user can see and/or edit individual fields across Salesforce access paths.

F

A Salesforce capability that coordinates longer multi-step processes involving multiple flows, approvals, or people.

The process that turns a qualified Lead into established customer/sales records: an Account and Contact, with an Opportunity created when applicable.

Profile-level controls that can restrict when and from which network ranges a user can log in.

M

The duplicate-management logic that determines how Salesforce identifies potentially duplicate records by comparing selected fields.

M

The structural layer of a Salesforce org, objects, fields, layouts, rules, flows, and other configuration that define how the org behaves.

An architecture model where multiple customers share underlying infrastructure while each customer org and its data remain isolated.

Sharing groups based on User manager relationships rather than only the Salesforce Role Hierarchy.

PRIORITIZATION
01
LEARN

Recognize what drives urgency

CORE IDEA

Urgency should match the real impact
